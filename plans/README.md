## Direction — options for the maintainer, not ranked against bugs

Grounded in `docs/analysis/comparable-platforms.md` (the repo's own August 2026
competitor read) and the code.

- **Per-kind minimum field widths** (analysis backlog #4). `src/lib/dashboard/grid.ts:34`
  has one global `MIN_W = 4` for every kind, and the 24-column grid now makes a
  per-kind floor meaningful. Small, pure, and already testable in
  `grid.test.ts`. Trade-off: existing narrow boxes of a now-larger kind need a
  clamp-on-read, not a migration.
- **Touch-target audit and a real-phone pass on dashboards** (analysis #5–6). The
  doc says all mobile verification so far is arithmetic. Cheap, and it is the
  half of the product the doc itself calls behind.
- **Let a block's page outlive its block** (analysis #9, "speculative"). It is the
  one capability linking buys that "block is the page" doesn't. The model
  already half-supports it (standalone `pages` exist; `bodyRev > 0` guards
  pruning). Large, and it risks diluting the core idea. Worth a design spike
  before any build.

## Findings considered and rejected

- **Backfill of mis-anchored all-day rows** (considered with plan 006): a read-only check on 2026-09-24 found 0 affected rows. Every all-day row in production has `tz = 'UTC'`, and for UTC the old code produced the right instant. Worth a look separately: all-day rows get `tz = 'UTC'` because `engine.ts:116` falls back to `calendar.timeZone ?? "UTC"`, while timed events carry `Africa/Lagos`. Check the Google Calendar's zone setting.

- **Push notifications don't work in production**: documented expected state
  (`vercel.app` can't be verified in Search Console); not a bug.
- **Calendar-move detection inert, description round-trip unimplemented**:
  documented in `CLAUDE.md` Current State; known, not findings.
- **`zustand` / `googleapis` installed but unused**: documented in `CLAUDE.md`.
  Removal is a trivial cleanup, not worth a plan.
- **`router.refresh()` after actions that already `revalidatePath`** (dashboard
  view, field delete): plausible double render, but unverified that the action
  response alone delivers the new props here. Low leverage; revisit only with a
  measured trace.
- **`getDashboardsWithFields` runs two queries serially**: real (~270ms), but only
  on the pause menu's load. Fold into any future dashboards-query change rather
  than planning it alone.
- **`setState` in effects in `dashboard-view.tsx` / `field-row.tsx`**: lint
  passes at `2f44196`, so the React Compiler rule accepts these sites as
  written; not a finding.
- **Cron bearer stored in `cron.job` command text**: inherent to pg_cron +
  pg_net. The script already refuses localhost, and prod is HTTPS. Requiring
  `https:` in `scripts/schedule-sync.ts` is a one-line hardening, fine to fold
  into any future edit there.
- **Page actions revalidate `"page"` not `"layout"`**: couldn't confirm a stale
  sidebar from reading alone; needs a check in the running app before it is a finding.
